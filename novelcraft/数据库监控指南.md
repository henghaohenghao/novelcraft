## 快速开始

### 1. 启动监控服务

在服务器上执行：

```bash
cd /path/to/novelcraft

# 同时启动应用和监控服务
docker compose -f docker-compose.yml -f docker-compose.monitoring.yml up -d

# 或者只启动监控（如果应用已在运行）
docker compose -f docker-compose.monitoring.yml up -d
```

## 各工具详细说明

### 📊 Adminer - PostgreSQL 管理（最常用）

**功能**：
- 查看所有表和数据
- 执行 SQL 查询
- 导入/导出数据
- 查看表结构和索引

**使用示例**：
1. 访问 http://your-ip:8080
2. 填写登录信息（见上方表格）
3. 点击表名查看数据
4. 使用 "SQL 命令" 执行自定义查询

### 🔴 Redis Commander - Redis 管理

**功能**：
- 查看所有 Redis key
- 实时监控内存使用
- 查看 key 的值和类型
- 删除或修改 key

**使用技巧**：
- 左侧树形结构显示所有 key（按前缀分组）
- 支持搜索过滤
- 可以查看各数据库（db0, db1, db2）的使用情况

### 🌐 Neo4j Browser - 图数据库查询

**功能**：
- 可视化图谱关系
- 执行 Cypher 查询
- 查看节点和关系统计

**常用查询**：
```cypher
// 查看所有节点类型和数量
MATCH (n) RETURN labels(n), count(*)

// 查看所有关系类型
MATCH ()-[r]->() RETURN type(r), count(*)

// 可视化部分图谱
MATCH (n)-[r]->(m) RETURN n,r,m LIMIT 50
```

**注意**: 需要先在 docker-compose.yml 中取消注释 Neo4j 端口映射：
```yaml
ports: ["7474:7474", "7687:7687"]
```

### 📈 Grafana - 统一监控面板（最专业）

**功能**：
- 数据库性能指标（QPS、连接数、查询延迟）
- 容器资源使用（CPU、内存、网络）
- 自定义告警

**首次使用**：
1. 访问 http://your-ip:3001
2. 登录 admin / admin（首次会要求修改密码）
3. 点击 "Dashboards" → "Browse"
4. 点击 "Import dashboard"，输入以下 Dashboard ID：
   - **9628**: PostgreSQL 监控
   - **11835**: Redis 监控
   - **893**: Docker 容器监控

### 🔍 Prometheus - 原始指标查询

**适合**：开发人员调试、验证指标

**示例查询**：
```promql
# PostgreSQL 连接数
pg_stat_database_numbackends

# Redis 内存使用
redis_memory_used_bytes

# 容器 CPU 使用率
rate(container_cpu_usage_seconds_total[5m])
```

### 📦 cAdvisor - 容器资源监控

**功能**：
- 实时查看每个容器的 CPU、内存、网络、磁盘 IO
- 历史数据图表
- 容器进程列表

## 生产环境安全配置

### 方案A：使用 Nginx 反向代理 + 基础认证

```bash
# 安装 nginx 和工具
sudo apt install nginx apache2-utils -y

# 创建密码文件
sudo htpasswd -c /etc/nginx/.htpasswd monitor

# 配置 nginx
sudo tee /etc/nginx/sites-available/monitoring << 'EOF'
server {
    listen 80;
    server_name monitor.yourdomain.com;

    auth_basic "Monitoring Area";
    auth_basic_user_file /etc/nginx/.htpasswd;

    location /adminer/ {
        proxy_pass http://localhost:8080/;
    }
    location /redis/ {
        proxy_pass http://localhost:8081/;
    }
    location /grafana/ {
        proxy_pass http://localhost:3001/;
    }
}
EOF

sudo ln -s /etc/nginx/sites-available/monitoring /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

### 方案B：限制 IP 访问

修改 `docker-compose.monitoring.yml`，只监听本地：
```yaml
ports:
  - "127.0.0.1:8080:8080"  # 只能本机访问
  - "127.0.0.1:8081:8081"
  - "127.0.0.1:3001:3000"
```

然后通过 SSH 隧道访问：
```bash
# 在你的本地电脑执行
ssh -L 8080:localhost:8080 \
    -L 8081:localhost:8081 \
    -L 3001:localhost:3001 \
    user@your-server-ip

# 然后在本地浏览器访问 http://localhost:8080
```

### 方案C：使用防火墙限制端口

```bash
# 只允许特定 IP 访问监控端口
sudo ufw allow from YOUR_HOME_IP to any port 8080
sudo ufw allow from YOUR_HOME_IP to any port 8081
sudo ufw allow from YOUR_HOME_IP to any port 3001
```

## 常见问题

### Q1: Neo4j Browser 无法访问？
**解决**：在 `docker-compose.yml` 中取消注释 Neo4j 端口映射：
```yaml
neo4j:
  ports: ["7474:7474", "7687:7687"]
```
然后重启：`docker compose up -d neo4j`

### Q2: Grafana 没有数据？
**解决步骤**：
1. 检查 Prometheus 是否正常：访问 http://your-ip:9090/targets
2. 确保所有 target 状态为 "UP"
3. 在 Grafana 中验证数据源连接

### Q3: 监控服务占用太多资源？
**解决**：
- 只启动必要的服务（如只要 Adminer）
- 调整 Prometheus 采集间隔（在 prometheus.yml 中修改 `scrape_interval`）
- 限制 Grafana 历史数据保留时间

### Q4: 如何停止监控服务？
```bash
docker compose -f docker-compose.monitoring.yml down

# 如果要删除数据卷
docker compose -f docker-compose.monitoring.yml down -v
```

## 轻量级方案（资源有限时）

如果服务器资源紧张，只需要基本管理功能，可以只启动必要的服务：

```bash
# 只启动 Adminer 和 Redis Commander
docker compose -f docker-compose.monitoring.yml up -d adminer redis-commander
```

或者使用 Docker 命令单独启动：

```bash
# PostgreSQL 管理
docker run -d --name adminer \
  --network novelcraft_default \
  -p 8080:8080 \
  -e ADMINER_DEFAULT_SERVER=postgres \
  adminer

# Redis 管理
docker run -d --name redis-commander \
  --network novelcraft_default \
  -p 8081:8081 \
  -e REDIS_HOSTS=local:redis:6379 \
  rediscommander/redis-commander
```
