# NovelCraft V2.0 实现文档

## 概述

本文档描述 NovelCraft V2.0 的三个核心功能实现：

1. **多人实时协同（Yjs + Redis）**
2. **Temporal 工作流**
3. **风格迁移模型缓存**

## 1. 多人实时协同（Yjs + Redis）

### 架构设计

- **CRDT 算法**：使用 Yjs 实现无冲突协同编辑
- **消息广播**：通过 Redis Pub/Sub 实现跨进程消息分发
- **状态管理**：Redis 存储房间在线用户、光标位置等实时状态
- **持久化**：定期将 Yjs 文档快照保存到 PostgreSQL

### 核心组件

#### 1.1 数据模型 (`collaboration_models.py`)

- **CollaborationRoom**: 协同编辑房间，关联章节
- **CollaborationSession**: 用户会话记录
- **CollaborationEvent**: 事件日志（加入、离开、编辑等）

#### 1.2 服务层 (`collaboration_service.py`)

**主要功能**：
- `create_or_get_room()`: 创建或获取房间
- `join_room()`: 用户加入房间
- `leave_room()`: 用户离开房间
- `broadcast_yjs_update()`: 广播 Yjs 更新
- `update_cursor_position()`: 更新光标位置
- `save_snapshot()`: 保存文档快照

**Redis 键设计**：
- `room:{room_id}:users`: 房间在线用户集合
- `room:{room_id}:events`: 事件频道
- `room:{room_id}:yjs`: Yjs 更新频道

#### 1.3 WebSocket 路由 (`collaboration.py`)

**端点**：
- `WebSocket /api/collaboration/ws/{room_id}`: 实时协同连接
- `POST /api/collaboration/rooms`: 创建房间
- `GET /api/collaboration/rooms/{room_id}/users`: 获取在线用户

**消息类型**：
- `yjs_update`: Yjs 文档更新
- `cursor_update`: 光标位置更新
- `save_snapshot`: 保存快照
- `user_joined/left`: 用户加入/离开通知

### 使用流程

```
1. 客户端连接 WebSocket
   ↓
2. 服务端创建会话，加入房间
   ↓
3. 订阅 Redis 事件频道
   ↓
4. 接收/发送 Yjs 更新
   ↓
5. 广播到其他用户
   ↓
6. 定期保存快照
```

## 2. Temporal 工作流

### 架构设计

- **工作流编排**：使用 Temporal 管理长时间运行的创作流程
- **可靠性**：自动重试、超时控制、补偿逻辑
- **可观测性**：工作流状态追踪、执行历史
- **断点续传**：支持暂停、恢复、取消

### 核心组件

#### 2.1 工作流定义 (`book_creation_workflow.py`)

**BookCreationWorkflow**：整书创作工作流
```python
流程：
1. 生成大纲 (generate_outline)
2. 等待人工确认（可选）
3. 按序生成章节 (generate_chapter)
4. 发送完成通知 (send_completion_notification)
```

**ChapterRevisionWorkflow**：章节修订工作流
```python
流程：
1. 读取章节 (read_chapter)
2. 执行修订 (revise_chapter)
3. 保存新版本 (save_chapter_version)
```

#### 2.2 活动定义

- `generate_outline`: 调用规划 Agent 生成大纲
- `generate_chapter`: 调用写作流水线生成章节
- `send_completion_notification`: 发送完成通知
- `read_chapter`: 读取章节内容
- `revise_chapter`: 修订章节
- `save_chapter_version`: 保存版本

#### 2.3 服务层 (`temporal_service.py`)

**主要功能**：
- `start_book_creation()`: 启动整书创作
- `start_chapter_revision()`: 启动章节修订
- `get_workflow_status()`: 查询状态
- `cancel_workflow()`: 取消工作流
- `get_workflow_result()`: 获取结果

#### 2.4 Worker (`worker.py`)

独立进程运行，执行工作流和活动：
```bash
python -m backend.workflows.worker
```

#### 2.5 API 路由 (`workflows.py`)

**端点**：
- `POST /api/workflows/book-creation`: 启动整书创作
- `POST /api/workflows/chapter-revision`: 启动章节修订
- `GET /api/workflows/status/{workflow_id}`: 查询状态
- `POST /api/workflows/cancel/{workflow_id}`: 取消工作流
- `GET /api/workflows/result/{workflow_id}`: 获取结果

### 使用示例

```python
# 启动整书创作
workflow_id = await temporal_service.start_book_creation(
    project_id="proj-123",
    title="我的小说",
    synopsis="一个关于...",
    genre="玄幻",
    style="古龙",
    chapter_count=10,
    user_id="user-456",
)

# 查询状态
status = await temporal_service.get_workflow_status(workflow_id)

# 获取结果
result = await temporal_service.get_workflow_result(workflow_id, timeout=300)
```

## 3. 风格迁移模型缓存

### 架构设计

- **分层缓存**：Hot (显存) → Warm (内存) → Cold (磁盘/对象存储)
- **淘汰策略**：LRU + 访问频次混合
- **预加载**：热门风格常驻显存
- **动态加载**：按需加载冷门风格

### 核心组件

#### 3.1 数据模型 (`style_models.py`)

- **StyleTransferTask**: 风格迁移任务记录
- **StyleModelCache**: LoRA 权重缓存状态

#### 3.2 缓存管理器 (`style_cache_service.py`)

**StyleCacheManager**：

**缓存层级**：
- `hot_cache`: 显存中的热门风格（OrderedDict，LRU）
- `warm_cache`: 内存中的次热门风格
- 数据库记录 `cache_tier = "cold"` 的冷门风格

**主要方法**：
- `get_or_load_style()`: 获取或加载风格模型
- `_promote_to_hot()`: 提升到 hot 层
- `_demote_to_warm()`: 降级到 warm 层
- `_ensure_hot_capacity()`: 确保容量，必要时淘汰
- `_load_from_cold()`: 从 cold 加载
- `get_cache_stats()`: 获取统计信息

**缓存流程**：
```
1. 检查 hot cache → 命中返回
   ↓
2. 检查 warm cache → 命中提升到 hot
   ↓
3. 从 cold 加载 → 加入 hot
   ↓
4. 容量不足时淘汰 LRU 条目
```

#### 3.3 风格迁移服务 (`style_transfer_service.py`)

**主要功能**：
- `transfer_style()`: 执行风格迁移
- `get_task_status()`: 查询任务状态
- `list_available_styles()`: 列出可用风格
- `get_cache_stats()`: 获取缓存统计

**推理流程**：
```
1. 创建任务记录
   ↓
2. 获取或加载风格模型（自动缓存管理）
   ↓
3. 调用 vLLM 执行推理
   ↓
4. 记录耗时和缓存命中情况
   ↓
5. 返回转换结果
```

#### 3.4 API 路由 (`style_transfer.py`)

**端点**：
- `POST /api/style-transfer/transfer`: 执行风格迁移
- `GET /api/style-transfer/task/{task_id}`: 查询任务状态
- `GET /api/style-transfer/styles`: 列出可用风格
- `GET /api/style-transfer/cache/stats`: 获取缓存统计

### 使用示例

```python
# 执行风格迁移
result = await style_transfer_service.transfer_style(
    original_text="这是一段普通的文本。",
    style_id="gulong",
    project_id="proj-123",
    db=db,
)

# 查看缓存统计
stats = style_transfer_service.get_cache_stats()
# {
#   "hot_cache": {"size": 3, "usage_mb": 386.6, "utilization": 18.88},
#   "warm_cache": {"size": 2, "usage_mb": 257.8, "utilization": 3.15},
#   "stats": {"total_requests": 150, "hit_rate": 87.33}
# }
```

### 缓存优化策略

1. **预加载热门风格**：启动时加载常用风格到 hot cache
2. **项目关联预热**：用户选择风格后异步预加载
3. **容量动态调整**：根据 GPU 显存实际情况调整 hot_capacity
4. **监控与告警**：通过 Prometheus 监控命中率、加载延迟

## 监控指标

### 风格迁移缓存

- `style_cache_hit_rate`: 缓存命中率
- `style_cache_hot_usage_mb`: Hot 层使用量
- `style_cache_evictions_total`: 淘汰次数
- `style_inference_time_ms`: 推理耗时

### 协同编辑

- `collaboration_active_rooms`: 活跃房间数
- `collaboration_active_users`: 在线用户数
- `collaboration_message_rate`: 消息速率

### Temporal 工作流

- `workflow_execution_time`: 工作流执行时间
- `workflow_success_rate`: 成功率
- `activity_retry_count`: 活动重试次数

## 性能优化建议

### 风格迁移

1. 增加 hot cache 容量（需要更大显存）
2. 使用 SSD 存储 LoRA 权重（加快 cold 加载）
3. 批量推理（多个请求合并）

### 协同编辑

1. 使用 Redis Cluster 提高吞吐
2. 增加快照保存间隔（减少数据库写入）
3. 使用 CDN 加速 WebSocket 连接

### Temporal 工作流

1. 调整 Worker 并发数
2. 优化活动超时时间
3. 使用工作流缓存（相同输入复用结果）

## 故障排查

### 风格迁移失败

- 检查 vLLM 服务是否运行
- 验证 LoRA 权重文件路径
- 查看显存使用情况

### 协同编辑断连

- 检查 Redis 连接
- 验证 WebSocket 配置
- 查看网络延迟

### 工作流卡住

- 查看 Temporal Web UI (http://localhost:8233)
- 检查 Worker 日志
- 验证活动超时配置

## 后续优化方向

1. **风格迁移**：支持多 LoRA 组合、风格强度调节
2. **协同编辑**：支持离线编辑、冲突解决策略
3. **工作流**：支持分支剧情、并行章节生成
