# NovelCraft 前端技术文档

本文档详细描述 [novelcraft/frontend](novelcraft/frontend/) 当前 V1.0 实现的前端代码架构、模块划分、组件设计及实现逻辑。完整产品规划请参见 [技术文档.md](技术文档.md)。

| 类别 | 选型 | 版本 | 说明 |
| --- | --- | --- | --- |
| 框架 | Next.js | ^14.2.0 | App Router 模式，支持 SSR/SSG/CSR |

## 二、目录结构与架构设计

### 2.1 目录树

```
frontend/
├─ app/                       # App Router 根目录
│  ├─ layout.tsx              # 全局布局（顶部导航 + main 容器）
│  ├─ page.tsx                # 首页（着陆页，Server Component）
│  ├─ globals.css             # 全局样式（仅 Tailwind 三件套 + body 字体）
│  └─ projects/
│     ├─ page.tsx             # 项目列表 + 创建表单（Client Component）
│     └─ [id]/page.tsx        # 项目详情（大纲/人物/写作/图谱四个 tab）
├─ next.config.js             # Next 配置（output: standalone）
├─ tsconfig.json              # TS 配置（path alias: @/*）
├─ tailwind.config.js         # Tailwind 扫描路径
├─ postcss.config.js          # PostCSS 插件链
└─ package.json
```

### 2.2 架构特点

- **扁平结构**：仅 4 个页面文件 + 1 个布局，没有 `components/`、`hooks/`、`lib/` 等通用模块抽离，逻辑就近写在页面里
- **Server + Client 混合**：首页用 Server Component 渲染，交互页面用 Client Component
- **无状态管理**：当前版本未使用 Zustand，所有状态在组件内部用 `useState` 管理
- **原生数据请求**：未使用 TanStack Query，直接用 `fetch` + `useState` + `useEffect`

## 三、配置文件详解

### 3.1 [next.config.js](novelcraft/frontend/next.config.js)

```js
module.exports = { output: "standalone" };
```

`standalone` 模式让 `next build` 输出可独立运行的 server.js + 最小 node_modules，适合服务器/容器部署，不依赖原项目的 `node_modules`。

### 3.2 [tsconfig.json](novelcraft/frontend/tsconfig.json)

关键项：
- `"strict": true` — 全量严格类型检查
- `"jsx": "preserve"` — 由 Next 编译器接管 JSX 转换
- `"moduleResolution": "bundler"` — Next 14 推荐配置
- `"paths": { "@/*": ["./*"] }` — 用 `@/app/...` 替代相对路径

注意 `"target": "es5"` 是 Next 默认值，实际运行目标由 SWC/Next 决定，不影响产出。

### 3.3 [tailwind.config.js](novelcraft/frontend/tailwind.config.js)

```js
content: [
  "./app/**/*.{js,ts,jsx,tsx,mdx}",
  "./components/**/*.{js,ts,jsx,tsx,mdx}",
],
```

只扫描 `app/` 和 `components/`。当前没有 `components/` 目录，那一行可保留以备扩展。`theme.extend` 与 `plugins` 都为空，使用 Tailwind 默认配色与间距。

### 3.4 [postcss.config.js](novelcraft/frontend/postcss.config.js)

```js
plugins: { tailwindcss: {}, autoprefixer: {} }
```

最小配置：Tailwind 把原子类编译进 CSS，Autoprefixer 自动加浏览器前缀。

## 四、路由设计（App Router）

Next.js 13+ 的 App Router 用文件夹结构表达路由：

| 路由 | 文件 | 类型 | 说明 |
| --- | --- | --- | --- |
| `/` | [app/page.tsx](novelcraft/frontend/app/page.tsx) | Server Component | 着陆页 |
| `/projects` | [app/projects/page.tsx](novelcraft/frontend/app/projects/page.tsx) | Client Component | 项目列表 |
| `/projects/[id]` | [app/projects/[id]/page.tsx](novelcraft/frontend/app/projects/%5Bid%5D/page.tsx) | Client Component | 项目详情，`[id]` 为动态段 |

### 4.1 根布局 [app/layout.tsx](novelcraft/frontend/app/layout.tsx)

包裹所有路由的全局布局：

```tsx
<html lang="zh-CN">
  <body>
    <nav className="bg-gray-900 text-white p-4">
      {/* 顶部导航栏 */}
      <Link href="/">NovelCraft</Link>

```

`children` 由 Next 自动注入对应路由的 `page.tsx`。`metadata` 导出供 SEO 使用。

#### 5.3.4 数据加载

5 个并行 fetch：项目、大纲树、人物、章节、图谱。每个用 `useCallback` 包裹后放进同一个 `useEffect`：

```ts
const fetchProject   = useCallback(async () => { /* 拉项目 */ }, [projectId]);
const fetchOutlines  = useCallback(async () => { /* 拉大纲树 */ }, [projectId]);
const fetchCharacters = useCallback(async () => { /* 拉人物 */ }, [projectId]);
const fetchChapters  = useCallback(async () => { /* 拉章节 */ }, [projectId]);
const fetchGraph     = useCallback(async () => { /* 拉图谱 */ }, [projectId]);

useEffect(() => {
  fetchProject(); fetchOutlines(); fetchCharacters(); fetchChapters(); fetchGraph();
}, [...]);
```

**为什么用 `useCallback`**：让这些函数也能在按钮回调里复用（生成大纲后调 `fetchOutlines()` 刷新），同时避免被 `useEffect` 依赖检查警告。

#### 5.3.5 Tab 切换

```ts
const [activeTab, setActiveTab] = useState<"outline" | "characters" | "writing" | "graph">("outline");
```

四个 tab 共享一个状态，渲染时用条件块展示，切换不卸载组件，但因为内容只读、无副作用，无需缓存。

#### 5.3.6 SSE 流式接收章节生成进度

这是前端最有技术含量的一段，对应后端 [writing.py:120-155](novelcraft/backend/routers/writing.py#L120-L155) 的 `text/event-stream` 响应：

```ts
const res = await fetch(`${API_URL}/api/writing/chapters/generate`, { method: "POST", ... });
const reader = res.body?.getReader();
const decoder = new TextDecoder();
let buffer = "";

while (true) {
  const { done, value } = await reader.read();
  if (done) break;

  buffer += decoder.decode(value, { stream: true });
  const lines = buffer.split("\n");
  buffer = lines.pop() || "";        // 保留可能不完整的最后一行

  for (const line of lines) {
    if (line.startsWith("data: ")) {
      const { event: evt, data } = JSON.parse(line.slice(6));
      if (evt === "status") {
        setStreamContent(prev => prev + `[${data.status}] ${data.message}\n`);
      } else if (evt === "result") {
        fetchChapters();
      }
    }
  }
}
```

**要点**：
- 用 `fetch().body.getReader()` 而不是 `EventSource`，因为 `EventSource` 仅支持 GET，这里是 POST
- 按 `\n` 分行 + `buffer.pop()` 处理跨 chunk 的不完整行，是 SSE 解析的标准技巧
- `evt === "status"` 累加到日志面板，`evt === "result"` 触发章节列表刷新（不直接用流里的 content，避免与服务端持久化结果不一致）

#### 5.3.7 大纲树递归渲染

后端 [outlines.py:42-73](novelcraft/backend/routers/outlines.py#L42-L73) 已经把大纲拼成嵌套 JSON，前端做递归即可：

```tsx
const renderOutlineTree = (nodes: Outline[], level: number = 0) => {
  return nodes.map((node) => (
    <div key={node.id} style={{ marginLeft: level * 24 }}>
      {/* 节点内容 */}
      {node.children && renderOutlineTree(node.children, level + 1)}
    </div>
  ));
};
```

用 `marginLeft = level * 24` 表达层级缩进，简单粗暴但够用。

#### 5.3.8 关系图谱降级展示

[backend/main.py:69-72](novelcraft/backend/main.py#L69-L72) 暴露了 Neo4j 可用性，但前端没读这个标志，而是直接展示 `graph.nodes` / `graph.edges`：
- Neo4j 可用：拿到节点 + 边，按 `labels[0]`（Character/Faction/Location/Event）配色显示
- Neo4j 不可用：节点和边都为空数组，前端展示"暂无关系数据"

技术文档里规划的 ECharts/D3 关系图当前**未实现**，只是一个分类徽章列表 + 边描述列表。React Flow 库已经装但还没用。

#### 6.5.3 AI 生成章节（流式）

| 属性 | 值 |
| --- | --- |
| **接口名称** | AI 生成章节（流式） |
| **请求 URL** | `/api/writing/chapters/generate` |
| **HTTP 方法** | POST |
| **Content-Type** | `text/event-stream` |
| **接口功能** | 触发多智能体循环生成章节，SSE 流式推送进度 |
| **调用场景** | 用户在章节写作 Tab 点击"AI 生成"按钮 |

**请求参数**（JSON Body）：

| 参数名称 | 类型 | 必填性 | 说明 |
| --- | --- | --- | --- |
| chapter_id | string | 必填 | 章节 UUID |
| style | string | 可选 | 写作风格，不传时使用项目默认风格 |

**SSE 事件格式**：

流式响应包含两种事件：

1. **status 事件**（推送进度）：
```
data: {
  "event": "status",
  "data": {
    "status": "planning|writing|reviewing|revising|...",
    "message": "正在制定写作计划..."
  }
}
```

2. **result 事件**（最终结果）：
```
data: {
  "event": "result",
  "data": {
    "chapter_id": "uuid",
    "title": "章节标题",
    "content": "完整章节内容",
    "summary": "章节摘要"
  }
}
```

**前端处理逻辑**：
- `evt === "status"`：累加到 `streamContent` 展示日志
- `evt === "result"`：调用 `fetchChapters()` 刷新列表（不直接用流里的 content）

## 十一、后续扩展建议

### 11.1 代码组织优化

1. **沉淀公共组件**：创建 `components/` 目录，把按钮、表单字段、徽章、模态框抽出
2. **抽取自定义 Hooks**：创建 `hooks/` 目录，把 `useSSE`、`useAPI` 等逻辑抽出
3. **工具函数库**：创建 `lib/` 目录，存放 API client、格式化函数等

### 11.2 状态管理与数据请求

1. **接入 TanStack Query**：替代 `useState` + `fetch`，统一缓存、自动重取、乐观更新
2. **引入 Zustand**：管理全局 UI 状态（如当前打开的项目、通知等）

### 11.3 功能增强

1. **章节编辑器升级**：换 Tiptap，支持 Markdown、批注、`@` 提及人物
2. **关系图谱可视化**：使用 React Flow 或 ECharts 实现交互式图谱
3. **大纲拖拽调整**：使用 React Flow 实现大纲树的可视化拖拽
4. **实时协作**：除 SSE 外，对协同编辑场景加一个 WebSocket（Socket.IO）层
5. **类型自动同步**：用 `openapi-typescript` 直接从后端 `/openapi.json` 生成 TS 类型，避免手动维护 interface 与 Pydantic schema 漂移
6. **错误处理统一**：当前所有 fetch 都没有 catch，失败静默。建议加一个 `fetcher` 包装 + toast 提示
7. **加载状态优化**：添加骨架屏、loading 动画，提升用户体验

### 11.4 性能优化

1. **图片懒加载**：后续添加图片功能时实现
2. **虚拟滚动**：大纲/章节列表变长时使用
3. **代码分割**：按路由分割 bundle，减少首屏加载时间
